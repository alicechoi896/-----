# SCRIPT_FORMATS — 대본 포맷 (영상 대본 구조)

> v0.9.26. **나의 스타일 = 어떻게 말할지(말투·표현)**, **대본 포맷 = 어떤 순서로 쓸지(구조·리듬)**.

## 1. 흐름

```
참고 대본 (메모장 .txt 여러 개 / 직접 입력, 최대 30개)
  → [AI 로 포맷 만들기]  (POST /api/script-formats/analyze, 프롬프트 script.format-extract)
  → 포맷 가이드라인 (사용자가 고쳐 저장)
  → 영상·클립 생성 때 [대본 포맷] 블록으로 들어간다
```

- **유형** 2가지: `product`(제품 홍보 영상·제품 홍보 클립) / `info`(정보성 영상·정보성 클립). 블로그는 대본이 없어 쓰지 않는다 (`scriptFormatTypeOf`)
- 유형마다 **기본 포맷 1개(★)**
- **나의 스타일에서 포맷 고르기** (v0.9.27): 스타일마다 `제품 홍보 포맷`·`정보성 포맷` (user_styles.product_format_id / info_format_id). 비우면 기본 포맷
- **적용 순서**: ① 생성 폼의 **대본 포맷** 칸에서 고른 것 → ② 이번 생성에 쓰인 스타일(고른 스타일 또는 채널 기본 스타일)에 연결된 포맷 → ③ 그 유형·채널의 기본 포맷(★) (`chooseScriptFormat`)
- 포맷을 지우면 스타일 연결만 풀린다 (DB `on delete set null`)
- 적용 채널(YouTube·NAVER 클립)을 고르면 그 채널에서만 기본 포맷으로 쓴다. 비우면 둘 다
- 이 유형의 첫 포맷은 자동으로 기본이 된다

## 2. 메모장 파일 나누기 (`lib/script-format.ts` `parseScriptFile`)

브라우저에서 파일을 읽고 대본 단위로 나눈다 (서버로 파일을 올리지 않는다, 1MB 까지).

| 기준 | 예 |
|------|-----|
| 구분선 | `-----`, `=====` |
| 빈 줄 2개 이상 | |
| 조회수 줄 (다음 대본의 조회수) | `4.2만회`, `1만`, `5.4천회` |
| 새 제목 줄 | `제목 : …`, `📌 제목`(다음 줄이 제목), `🎬 제목:`, `제목,썸넬 :` |

- 뺀다: `썸넬 …`, `🎬 쇼츠 스크립트`, `<채널이름>`, `[음악]`
- 30자 미만 조각(메모)은 버리고, 같은 본문은 한 번만
- 결과는 화면에서 확인·수정 후 저장한다

## 3. 생성에 넣는 방식 (`lib/server/ai/prompts/render.ts`)

> v0.9.28: 포맷은 **구조 참고**다. 큰 흐름은 살리되 단계를 합치거나 순서·강조점·표현을 바꿔 더 설득력 있게 다시 짠다. 대본은 **3편**(편마다 Hook·전개·CTA 를 다르게)으로 만들어 골라 섞어 쓰게 한다.
> 참고 대본의 **잘된 제목**(조회수 높은 순 5개)은 영상 제목, 그리고 **블로그 글 제목**(제품 글 → 제품 홍보 포맷, 정보 글 → 정보성 포맷)에 패턴으로만 쓴다 (`promptTitles`, `blogTitleFormatTypeOf`).

- **가이드라인 전부** + **참고 대본 2개**(조회수 높은 순, 각 500자) — 구조·리듬만 참고, 문장·제품명·숫자 복사 금지, 받아 적은 오타 따라 하지 않기
- 영상 길이와 말투 규칙('~니다.' 금지, 짧은 리듬)은 그대로
- 가격·할인·배송·순위 주장은 **[제품 정보]에 근거가 있을 때만** (정직성 규칙이 포맷보다 우선)
- 생성 기록 `context.scriptFormat` 에 쓴 포맷 이름이 남고, 결과 화면 "이번 생성에 사용된 학습 데이터"에 보인다
- 테이블이 아직 없으면(schema.sql 재실행 전) 포맷 없이 생성한다 (고른 포맷이 있을 때만 오류)

### 제목만 담기 (v0.9.30)

트렌드 찾기(YouTube 표·NAVER 급상승 주제·콘텐츠 아이디어)와 영상 검색의 **[대본 포맷에 담기]**는 `{ title, views, text: "" }` 를 참고 대본 목록 위에 더한다 (`POST /api/script-formats/titles`, 기존 포맷 또는 새 포맷).
제목만 담긴 참고는 **제목 패턴**(`promptTitles`)에만 쓰고, 대본 예시(`promptExamples`)와 AI 구조 분석(`analyze`)에서는 뺀다. 같은 제목은 다시 넣지 않고, 30개 한도를 넘으면 빼고 알려 준다.

### Hook·CTA·제목 패턴 · 블로그 포맷 · 피해야 할 대본 (v0.9.37)

- 역할: 콘텐츠 프로필 = 무엇을·누구에게, 나의 스타일 = 말투(톤·규칙·금지·표현), 대본 포맷 = 구조·설득 방식(대본 뼈대·Hook·CTA·제목).
- 포맷의 `hooks`·`ctas`·`titlePatterns`·`preferredTypes`가 있으면 생성할 때 스타일의 같은 항목 대신 쓴다. `context-builder.ts`의 `mergeFormatPersuasion`이 이 일을 하며, 항목별로 판단하고 비어 있으면 스타일 것을 쓴다. 스타일이 없어도 포맷 것을 쓴다.
- 적용 순서는 그대로다(생성 화면에서 고른 포맷 → 스타일에 연결한 포맷 → 기본 ★). 같은 조건이면 그 채널을 직접 고른 포맷이 '모든 채널' 포맷보다 먼저다.
- **블로그 포맷**: `channelIds`에 `naver-blog`. 유형(제품 홍보·정보성)은 그대로 쓰므로 `content_type` 제약은 바꾸지 않는다. 블로그는 대본·가이드라인을 쓰지 않고 Hook(도입)·CTA(마무리)·제목 패턴·잘된 제목만 쓴다.
- **[대본 포맷으로 복사]**(나의 스타일 카드): 누를 때만 고른 포맷에 더한다. 같은 문장은 한 번만, 한도 안에서. 스타일 값은 지우지 않는다.
- **피해야 할 대본** `badExamples`(대본 있는 것만, 최대 10개): 영상·클립 생성 때 2개만 300자로 줄여 "이렇게 쓰지 않는다" 블록으로 보낸다.

## 4. 데이터 (`script_formats`)

| 컬럼 | 설명 |
|------|------|
| id, user_id | 본인 것만 (RLS own_rows 와 같은 규칙) |
| name | 40자 |
| content_type | `product` / `info` |
| channel_ids | `youtube`, `naver-clip` (비면 둘 다) |
| examples | jsonb `[{ title, views, text }]` 최대 30개, 본문 2,000자 |
| guideline | 3,000자 |
| is_default | 유형마다 1개 |

## 5. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/script-formats` | 내 포맷 (생성 화면 선택지) |
| POST | `/api/script-formats` | 만들기 (`ai-learning` 권한) |
| PUT / PATCH / DELETE | `/api/script-formats/:id` | 수정 / 기본으로 / 삭제 |
| POST | `/api/script-formats/analyze` | 참고 대본 → 가이드라인 (AI 1회, 저장 안 함, 1분 20회 한도 공유) |
