## 1. 서비스 목적

**콘텐츠 자동화 센터**(임시 서비스명)는 YouTube, NAVER 클립, NAVER 블로그 콘텐츠를 만드는 1인 크리에이터, 셀러, 마케터가
**소재 조사 → 기획 → 제목·대본·글 작성 → 키워드·해시태그 정리**까지 반복해서 하는 일을 한 곳에서 자동화하는 업무용 웹서비스다.

이 서비스의 차별점은 "AI에게 매번 처음부터 설명하지 않는다"는 것이다.
제품 정보, 사용자 스타일, 과거의 좋은 결과물, 성과 데이터를 **저장해 두고, 생성할 때마다 자동으로 Context로 주입**한다.
쓸수록 결과물이 사용자에게 맞춰진다.

## 2. 문제 정의

| # | 문제 | 현재 사용자가 하는 일 | 서비스가 하는 일 |
|---|------|----------------------|------------------|
| P1 | 채널마다 도구가 흩어져 있다 | YouTube 분석 사이트, 네이버 데이터랩, ChatGPT, 메모장을 오간다 | 채널별 자동화 기능을 한 화면 구조(채널 → 기능 → 실행)로 묶는다 |
| P2 | 같은 제품을 매번 다시 설명한다 | 상세페이지를 복사해 ChatGPT에 붙여넣는다 | 상세페이지를 **한 번만** 분석해 제품 라이브러리에 저장하고 재사용한다 |
| P3 | AI 결과 품질이 호출마다 다르다 | 프롬프트를 매번 새로 쓰고, 결과는 운에 맡긴다 | 고정 프롬프트(버전 관리)와 저장 데이터(Memory)를 함께 써서 품질을 일정하게 유지한다 |
| P4 | 좋은 결과물이 쌓이지 않는다 | 잘된 제목이나 대본을 따로 저장하지 않는다 | 생성 이력, 피드백, 성과를 저장하고 다음 생성의 참고 예시로 쓴다 |
| P5 | 트렌드 조사에 시간이 많이 든다 | 조회수와 게시일을 직접 비교한다 | 기간별 조회 속도와 Trend Score로 잘되는 소재를 정렬해 보여준다 |
| P6 | 허위·과장 표현의 위험 | AI가 "직접 써봤다"는 허위 후기를 만들어낸다 | 실제 경험을 입력하지 않으면 사용 후기 표현을 금지하는 가드레일을 둔다 |

## 3. 사용자

| 페르소나 | 설명 | 주요 사용 기능 |
|----------|------|----------------|
| **제휴 마케터 / 셀러** | 쿠팡 파트너스, 스마트스토어 제품을 영상·블로그로 홍보한다 | 제품 상세페이지 학습, 제품 라이브러리, 제품 홍보 영상·클립·블로그 |
| **정보형 크리에이터** | IT, AI, 생활정보 채널을 운영한다 | 트렌드 찾기, 정보성 영상·클립·글 |
| **소규모 마케팅 담당자** | 회사 제품을 여러 채널에 동시에 노출해야 한다 | 제품 라이브러리, 채널별 생성, 스타일 관리 |

공통 특성: **PC에서 업무로 사용**하고, 같은 작업을 하루에 여러 번 반복하며, 결과물을 복사해서 각 플랫폼에 붙여넣는다.

## 4. 핵심 가치

1. **채널 중심 구조**: 사용자는 "어디에 올릴지"를 먼저 정하고, 그다음 할 일을 고른다.
2. **한 번 분석, 계속 재사용**: 제품 정보는 Product Library에 구조화해 저장한다.
3. **쓸수록 나아지는 AI**: Memory(제품, 스타일, 이력, 피드백, 성과)를 Context로 주입한다. Fine-tuning이 아니다.
4. **정직한 콘텐츠**: 경험하지 않은 사용 후기는 만들지 않는다.
5. **내 API 사용(BYOK)**: 사용자가 자기 OpenAI, YouTube, NAVER API Key를 연결한다. Key는 서버에서만 암호화해 다룬다.
6. **업무용 UI**: 흰색 기반의 깔끔한 SaaS UI, 데스크톱 우선.

**Channel → Feature → Tool 3단계 구조**

| 단계 | 화면 | 역할 | 예 |
|------|------|------|----|
| 1차 | 채널 선택 (메인) | 어디에 올릴 콘텐츠인지 고른다 | YouTube 카드 클릭 |
| 2차 | 채널 허브 | 그 채널의 자동화 기능 카드를 보여준다 | "제품 홍보 영상 만들기" 카드 클릭 |
| 3차 | 기능 실행 화면 | 입력 → 실행 → 결과 | 제품 선택 → 생성 → 복사·저장 |

메인 화면에는 세부 기능을 노출하지 않는다. 기능이 30개 이상으로 늘어도 1차 화면은 채널 카드만 보이므로 복잡해지지 않는다.

## 6. 주요 사용자 흐름

### 6.1 제품 홍보 콘텐츠 (핵심 흐름)

```
공통 도구 → 제품 상세페이지 학습
  → URL / 이미지 / 텍스트 입력 → [상세페이지 분석하기]
  → 분석 결과 확인 → [제품 라이브러리에 저장]
제품 라이브러리 → 제품 카드 [콘텐츠 만들기] → 채널 선택 (영상 / 클립 / 블로그)
  → 제품이 미리 선택된 생성 화면 → 옵션 입력 → [생성하기]
  → 결과(제목 5개, Hook, 대본, 설명글, 키워드, 해시태그)
  → 섹션별 복사 / 좋아요·별로예요 / 좋은 결과로 저장
```

### 6.2 트렌드 기반 정보성 콘텐츠

```
YouTube → YouTube 트렌드 찾기 → 기간·카테고리 필터 → Trend Score로 정렬
  → 소재 확인 → YouTube → 정보성 영상 만들기 → 트렌드 선택 → 생성
```

### 6.3 처음 사용하는 사용자

```
설정 → API 연결 센터 → OpenAI 키 연결 → [테스트]
AI 학습 관리 → 나의 스타일 → 기본 스타일 등록
이후 모든 생성에 스타일이 자동으로 반영된다
```

## 7. 기능 정의

> 기능별 상태, 필요 API, 입출력은 [FEATURE_REGISTRY.md](./FEATURE_REGISTRY.md)가 단일 기준이다. 여기서는 목적과 규칙을 정의한다.

### 7.1 메인 — 채널 선택
- 제목 "콘텐츠 자동화 센터", 설명 "작업할 채널을 선택하세요."
- 채널 카드 4개(YouTube, NAVER 클립, NAVER 블로그, 공통 도구). 각 카드에는 아이콘, 이름, 한 줄 설명, 바로가기, 기능 수가 있다.
- 하단 보조 영역: 최근 생성 콘텐츠, 제품 라이브러리 현황, API 연결 상태 요약.

### 7.2 YouTube
| 기능 | 목적 | 핵심 규칙 |
|------|------|-----------|
| 01 YouTube 트렌드 찾기 | 최근 7/14/21일 동안 잘되는 영상, 주제, 키워드를 찾는다 | 필터: 카테고리, 검색 키워드, 기간, Shorts/일반, 정렬. 결과 표: 썸네일, 제목, 채널, 게시일, 조회수, 일평균 조회수, 주요 키워드, Trend Score |
| 02 제품 홍보 영상 만들기 | 저장된 제품으로 홍보 영상 원고를 만든다 | 입력: 제품, 참고 트렌드, 주요 키워드, 참고 영상, 영상 길이, 콘텐츠 스타일. 출력: 추천 제목 5개, Hook, 대본, 설명글, 주요 키워드, 해시태그 |
| 03 정보성 영상 만들기 | 제품과 상관없는 정보 콘텐츠 | 입력: 카테고리, 주제, 트렌드, 주요 키워드, 영상 길이. 출력: 추천 주제, 제목, Hook, 대본, 설명글, 키워드 |

**Trend Score (V1 정의)** — 0~100 정규화 점수
`일평균 조회수(조회 속도) 50% + 구독자 대비 조회 비율 30% + 최근성 20%`
산식은 `lib/domain/trend-score.ts`에 하나만 두고, 바꾸면 문서도 함께 갱신한다.

### 7.4 NAVER 블로그
| 기능 | 목적 | 핵심 규칙 |
|------|------|-----------|
| 01 네이버 트렌드·키워드 찾기 | 블로그 글감과 키워드를 찾는다 | UI: 검색어, 관련 검색어, 최근 검색 추이, 급상승 키워드, 시즌 키워드, 콘텐츠 아이디어 |
| 02 제품 블로그 글 만들기 | 제품 리뷰·소개 글 | 입력: 제품, 메인 키워드, 서브 키워드, 글 스타일, 글 길이, 실제 경험(선택). 출력: 제목 후보, 전체 본문, 소제목, 제품 장점, 정보, CTA, 키워드, 해시태그 |
| 03 정보·트렌드 글 만들기 | 제품이 없는 정보 글 | 유형: 일반 정보, 트렌드, IT, AI, 생활정보 |
| 04 자동 글쓰기 | 최소 입력으로 전체 글 생성 | 저장된 스타일, 제품, 히스토리를 최대한 활용한다. 입력은 주제(필수)와 유형 정도만 받는다 |

**정직성 규칙 (필수)**: "실제 경험" 입력이 비어 있으면 AI는 "직접 사용해봤다", "써보니" 같은 1인칭 사용 후기 표현을 쓸 수 없다.
제품 정보를 근거로 한 "소개·정리" 형식으로만 쓴다. 이 규칙은 프롬프트 템플릿의 가드레일과 Mock 출력 양쪽에 반영되어 있다.

### 7.5 공통 도구
| 기능 | 목적 |
|------|------|
| 01 제품 상세페이지 학습 | 쿠팡, 스마트스토어 등의 상세페이지를 분석해 구조화된 제품 데이터를 만든다 |
| 02 제품 라이브러리 | 분석한 제품을 저장·조회·수정·삭제하고 콘텐츠 생성으로 연결한다 |
| 03 영상 URL 가져오기 | 참고할 영상 URL을 등록하면 메타데이터(제목, 채널, 길이)를 저장한다. 제품 홍보 영상의 "참고 영상"으로 쓴다 |

> "무음 제거 + 자막" 기능은 V1 범위에서 제외한다.

#### 제품 상세페이지 학습 상세
- 입력 탭 3개: **URL 입력(기본)** / 이미지 업로드 / 텍스트 직접 입력
- 안내 문구: "URL 접근이 불가능한 경우 상세페이지 이미지 또는 텍스트를 직접 입력할 수 있습니다."
- 분석 결과는 3개 섹션으로 보여준다.
  - **기본 정보**: 제품명, 브랜드, 카테고리, 판매처, URL
  - **AI 제품 요약**: 한 줄 설명, 핵심 특징, 핵심 장점, 차별점, 추천 대상, 구매 포인트, 주의할 점
  - **콘텐츠 제작용 데이터**: 영상 강조 포인트, 블로그 강조 포인트, 추천 키워드, 추천 Hook, 사용하면 안 되는 표현
- [제품 라이브러리에 저장] 버튼을 누르면 라이브러리에 저장되고, 상세 화면으로 이동할 수 있다.
- 처리 파이프라인: `URL → Product Data Collector → Raw Product Data → AI Analyzer → Structured Product Data → Product Library`
  Collector(수집)와 Analyzer(분석)는 **반드시 분리**한다. 수집처가 늘어나도 분석 로직은 그대로 쓰고, AI 모델이 바뀌어도 수집 로직은 그대로 쓴다.

#### 제품 라이브러리 상세
- 카드 / 목록 보기 전환, 검색, 카테고리 필터
- 카드 항목: 대표 이미지, 제품명, 브랜드, 카테고리, 주요 장점, 저장일, 최근 사용일
- 버튼: 상세보기, 수정, 콘텐츠 만들기(영상 / 클립 / 블로그 선택), 삭제
- 제품 상세: 저장된 모든 분석 데이터, 원본 수집 데이터, 이 제품으로 만든 콘텐츠 이력
- **콘텐츠를 생성할 때 상세페이지를 다시 분석하지 않는다.** 저장된 분석 결과를 재사용하고 `lastUsedAt`만 갱신한다.

### 7.6 AI 학습 관리
- 탭: **콘텐츠 프로필** / 제품 데이터 / 나의 스타일 / 콘텐츠 히스토리 / 피드백 / 성과 데이터
- **콘텐츠 프로필 = 무엇을 다룰 것인가** (대표 카테고리·세부 관심분야·관심 키워드·제외 키워드·국가·기본 분석기간). 기본 프로필 1개가 트렌드 화면 3개와 콘텐츠 생성에 자동으로 적용된다. 그래서 트렌드 화면에 들어갈 때마다 카테고리·키워드를 다시 입력하지 않는다. "나의 스타일"(어떻게 표현할 것인가)과는 합치지 않는다. 자세한 내용은 [CONTENT_PROFILE.md](./CONTENT_PROFILE.md)를 본다.
- UX 원칙: 채널 선택은 메뉴에 들어가는 것으로 끝난다. 프로필이 1개면 고르는 절차 없이 자동 적용하고, 2개 이상일 때만 트렌드 화면 위쪽 바에서 전환한다.
- "AI 학습"은 Fine-tuning이 아니라 **저장 데이터의 Context Injection**이다. 자세한 내용은 [AI_LEARNING_SYSTEM.md](./AI_LEARNING_SYSTEM.md)를 본다.
- V1: DB 구조, UI, 생성할 때 Context를 조립하는 흐름(`ContextBuilder`)을 구현한다. 성과 데이터 자동 수집은 이후 단계에서 한다.

### 7.7 설정 — API 연결 센터
- Provider: OpenAI / YouTube Data API / NAVER API(Client ID와 Client Secret)
- 각 카드: 상태(미연결/연결됨/오류), [연결하기], [테스트], 연결 해제
- API Key는 서버로만 전송하고, 서버에서 AES-256-GCM으로 암호화해 저장한다. 프론트엔드에는 마스킹된 값(`sk-…ab12`)만 돌려준다.
- localStorage에 Key를 저장하지 않는다.

## 12. 향후 개발 방향

1. **영구 저장소**: Supabase(Postgres) Repository 구현으로 교체 ([DATA_MODEL.md](./DATA_MODEL.md)에 테이블 설계 포함)
2. **인증**: Supabase Auth, 사용자별 데이터와 API Key 분리
3. **실제 Provider**: OpenAI(구현됨, 활성화만 필요) → YouTube Data API → NAVER DataLab·검색 API
4. **실제 Collector**: 스마트스토어/쿠팡 수집(공식 API 또는 서버 측 수집), 이미지 OCR(Vision 모델)
5. **AI Memory 고도화**: 좋은 결과물 임베딩 검색(RAG), 피드백 기반 스타일 자동 보정
6. **성과 연동**: YouTube Analytics, 블로그 통계, 판매 데이터 → Performance Data
7. **추가 채널**: Instagram Reels, TikTok, Threads (Registry에 채널 1개를 추가)

자세한 순서는 [NEXT_STEPS.md](./NEXT_STEPS.md)를 본다.
