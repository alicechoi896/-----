# 프롬프트 버전별 성과 · 성과 비교 학습 (v0.9.34, 품질 2단계)

## 1. 프롬프트 버전별 성과표

AI 학습 관리 › **성과 데이터** 탭 맨 위에 있습니다. `GET /api/performance/prompts` → `memoryService.promptStats()` → `promptVersionStats()`(`lib/domain/prompt-stats.ts`).

**묶는 기준**: 프롬프트 id + 버전 + 생성 방식(빠른 / 정밀 = `context.quality.mode`)

| 값 | 계산 |
|---|---|
| 생성 | 생성 결과 수 |
| 👍 비율 | 결과마다 **마지막** 피드백 기준, 👍 ÷ (👍 + 👎) |
| 직접 수정 | 고친 결과의 비율 · 고친 결과의 평균 수정 정도(항목별 수정 비율 중 최대값), 적을수록 좋음 |
| 업로드율 | 업로드 관리에 연결된 결과 ÷ 생성 |
| 평균 조회수 | 결과마다 가장 큰 조회수의 평균 (YouTube 1·7일 자동 + 직접 입력) |

- 같은 프롬프트·생성 방식에서 **바로 이전 버전보다 좋아진 값**은 초록색으로 표시합니다.
- 괄호 안은 표본 수입니다.
- 기존 데이터만 읽어서 계산하므로 DB에 저장하지 않습니다. 내 생성 이력만 대상입니다.

## 2. 성과 비교 학습 (상위 3 vs 하위 3)

학습 프로필을 업데이트할 때(`learningService.update`) 함께 처리합니다.

**조건**: 같은 학습 프로필(채널·유형)에서 조회수가 있는 콘텐츠가 6개 이상일 때만(`CONTRAST_CONFIG`) 비교합니다. 적으면 우연의 영향이 크기 때문입니다.

**처리**
- 콘텐츠별 가장 큰 조회수로 상위 3개와 하위 3개를 고릅니다(`performanceContrast`).
- 두 묶음의 요약(제목·Hook·대본 구조·CTA)을 `[성과 비교]` 블록으로 AI에 함께 보냅니다.
- 학습 규칙 8에 따라 결과를 나눠 적습니다.
  - 상위에만 있는 공통점 → title/hook/structure insights, positive_traits
  - 하위에만 있는 공통점 → negative_traits
  - 제품·시즌 차이로 설명되는 차이는 빼라고 지시합니다.

**언제 도는가**: 새 조회수가 들어오면 학습 신호가 됩니다(`scheduleLearning`). 들어오는 경로는 두 가지입니다.
- 업로드 1·7일 자동 수집 (업로드 관리 목록을 열 때)
- 조회수 직접 입력

새 신호가 10개 쌓이면 자동으로 업데이트하고, [지금 학습 업데이트]를 누르면 바로 업데이트합니다.

**비용**: 추가 AI 호출은 없습니다. 기존 학습 업데이트 1회의 프롬프트에 비교 블록만 더합니다(최대 6개 × 500자).
